## 📦 开发基座：IntelliJ IDEA + Gradle 项目

PaperKiteManor 的 GitHub 仓库是一个完整的 Forge Gradle 项目，包含 `src` 源码、`build.gradle`、`gradle/wrapper` 等。你不需要 MCreator，也不需要额外下载 Forge MDK。

**你的准备工作：**

```bash
# 1. Fork 一份到自己的 GitHub 账号
# 2. 克隆到本地
git clone https://github.com/<你的用户名>/PaperKiteManor.git
cd PaperKiteManor

# 3. 确认能编译通过
./gradlew build
```

**用 IDEA 打开项目：**

1. 安装 **JDK 17**（Minecraft 1.20.1 要求）
2. 安装 **IntelliJ IDEA Community Edition**
3. 用 IDEA 打开项目根目录的 `build.gradle`，IDEA 会自动识别为 Gradle 项目
4. 在右侧 Gradle 面板运行 `genIntellijRuns`，生成启动配置
5. 运行 `runClient`，确认开发环境正常

**Agent 如何介入：**

DeepSeek Harness 可以直接操作这个项目文件夹：
- 阅读 `src/main/java` 下的所有源码
- 修改和新增 Java 文件
- 运行 `./gradlew build` 验证编译
- 运行 `./gradlew runClient` 启动测试客户端

不需要任何中间插件，Agent 直接与文件系统和 Gradle 交互。

## 🎯 给 Agent 的提示词

### 项目背景与目标

```
你是一个 Minecraft Forge 模组开发 Agent。我正在开发 PaperKiteManor（纸鸢庄园），
一个 Minecraft 1.20.1 Forge 模组，使用 GeckoLib 作为依赖。

项目已克隆到当前工作目录。这是一个完整的 Gradle 项目，你可以：
- 运行 ./gradlew build 验证编译
- 运行 ./gradlew runClient 启动测试客户端
- 阅读 src/main/java 下的所有源码
- 修改和新增 Java 文件

核心目标：实现一个"实体收纳物品"（暂命名为"收纳符"），功能如下：

1. 手持空的收纳符右击已驯服的实体（白兔女仆、原版狼/猫等），
   将该实体的完整 NBT 数据保存到物品的 NBT 中，并从世界移除该实体。
2. 手持存有数据的收纳符右击地面，读取物品 NBT 中的实体数据，
   在目标位置重新生成完全一致的实体。
3. 存有实体的收纳符不可堆叠（maxStackSize=1）。

关键要求：
- 保留实体的 UUID，确保"同一性"
- 释放时覆盖 Pos、Dimension、Motion 等运行时字段
- 物品 NBT 中需要保存：实体类型 ID、完整实体 NBT、收纳时间戳
- 模组环境在开发期间不变动

参考实现：TouhouLittleMaid 的"魂符"（smart_slab）使用了类似的机制，
其女仆备份文件存放在存档的 data/maid_backups/<玩家UUID>/<女仆UUID>/ 目录下，
但我们的方案更倾向于将数据直接存在物品 NBT 中，而非外部文件。
```

### 第二阶段：实现收纳物品

```
【任务 2：实现收纳符物品】

基于任务 1 的侦察结果，实现收纳符。请按以下步骤：

1. 创建空收纳符物品类：
   - 继承 Item
   - 设置 maxStackSize = 1
   - 在物品栏中显示为普通物品

2. 创建满收纳符（或复用同一物品 + NBT 判断）：
   - 建议方案：同一物品，通过 NBT 中是否存在 EntityData 标签来区分空/满
   - 空符右击实体 → 收纳
   - 满符右击方块 → 释放

3. 实现收纳逻辑（在 Item#interactLivingEntity 或 UseOnContext 中）：
   - 检查目标实体是否可被收纳（已驯服 + 属于当前玩家）
   - 使用 entity.saveWithoutId(compoundTag) 保存实体完整 NBT
   - 额外保存实体类型 ID（EntityType.getKey(entity.getType()).toString()）
   - 将 compoundTag 写入物品的 NBT：itemStack.getOrCreateTag().put("EntityData", compoundTag)
   - 从世界移除实体

4. 实现释放逻辑（在 Item#useOn 中）：
   - 从物品 NBT 读取 EntityData
   - 通过 EntityType.byString() 获取实体类型
   - 在目标位置创建实体
   - 使用 entity.load(compoundTag) 恢复数据
   - 覆盖位置：entity.moveTo(blockPos.getX() + 0.5, blockPos.getY() + 1, blockPos.getZ() + 0.5)
   - 清除物品中的 EntityData（变为空符）

5. 注册物品：
   - 在物品注册类中注册收纳符
   - 加入创造模式物品栏
   - 添加中英文语言文件条目
   - 添加物品模型和材质（暂时可以用原版材质占位）

请先输出你计划创建/修改的文件列表和每个文件的核心代码，
确认方案后再实际写入文件。
```

## ⚠️ 需要留意的技术风险

**白兔女仆的 NBT 完整性**：如果它的数据不完全通过标准 `addAdditionalSaveData` 保存（比如用了 Capability 或自定义数据附件），Agent 在侦察阶段需要识别出来。TouhouLittleMaid 的任务数据就是通过 `EntityMaid.addAdditionalSaveData` 调用 `taskDataMaps.writeToNBT` 写入的，白兔女仆可能有类似的结构。

**UUID 冲突**：收纳时实体从世界移除，释放时保留原 UUID 是安全的。但如果同一个 UUID 在两个世界同时存在（比如旧世界没删干净），可能导致问题。建议在释放时给 Agent 加一个检查：如果世界中已存在相同 UUID 的实体，则生成新 UUID。

**GeckoLib 渲染状态**：白兔女仆使用 GeckoLib 做动画，实体 NBT 中可能包含动画状态字段。释放后需要确认动画能否正确恢复。

**物品 NBT 大小限制**：Minecraft 对 NBT 大小有隐式限制（约 2MB），女仆的 NBT 通常远小于此，但如果她的背包里有大量物品，需要留意。
